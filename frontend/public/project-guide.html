1What this project is

An internal operations system digitising the full service lifecycle for Sejuk Sejuk Service Sdn Bhd.

This is an internal operations system for Sejuk Sejuk Service Sdn Bhd (a fictional air-conditioning installation, servicing, and repair company). It digitises the full service lifecycle — from the moment a customer request arrives to the moment an order is closed and reflected on the KPI dashboard.

The system covers every module the assessment asks for: the Admin portal (order submission), the Technician portal (field service jobs), the WhatsApp notification trigger, a KPI dashboard, and an AI operations assistant — plus production-grade extras like audit history, private evidence storage, payments with receipts, notifications, internal messaging, and structured addresses.

One-line summary: an admin creates an order, a technician is assigned and completes the field work with checklist proof, the manager reviews and closes it, the dashboard updates — and an AI assistant can answer questions about all of it using only the data each user is allowed to see.

2The project workflow

Orders move through a six-state lifecycle, enforced in the database, not just in the UI.

1

New

Admin

Order intake with customer, structured address, service type, quote, notes. Optionally pre-filled by AI.

2

Assigned

Admin

Technician assigned, notified, and a WhatsApp handoff link becomes available.

3

In Progress

Technician

Start work, tick checklist items with notes and photo proof, upload evidence.

4

Job Done

Technician

Completion report with auto final amount, optional payment + receipt; manager notified.

5

Reviewed

Manager

Review completion, checklist proof, payments, warnings. Accept or return for correction.

6

Closed

Manager

Order archived; the KPI dashboard reflects the completed work.

Correction loop: when a manager returns a job, selected checklist items are reopened, the technician is notified, and the order returns to In Progress until reworked and re-submitted.

  New --> Assigned: Admin assigns (notification)
  Assigned --> InProgress: Technician starts

Every transition is a versioned, role-checked RPC that also writes an audit event with before/after values, so the entire history of an order is traceable and concurrent edits cannot silently overwrite each other.

3Roles & workspaces

Three roles, each with its own pages and capabilities — enforced server-side.

Admin

Pages: Orders, Payments, How it works

  • Create orders with auto-generated numbers and structured addresses
  • Assign technicians and customize checklists
  • Re-edit service details; open addresses in Google Maps
  • Collect outstanding payments with notes and attached receipts
  • Inspect the audit history of any order

Technician

Pages: Dashboard, My jobs

  • Mobile-first job queue scoped to their own assignments
  • Start / reschedule work; save checklist items with photo proof
  • Upload up to six private evidence files
  • Complete jobs with auto final amount and optional payment + receipt
  • Open a pre-filled WhatsApp feedback message for the customer

Manager

Pages: Dashboard, Reviews

  • Review completed jobs with deterministic warnings
  • Accept or return work (reopening selected items)
  • Close reviewed orders
  • Track KPIs: completed jobs, service value, payments, postponements
  • Ask the AI assistant about operations and workload

4Features in detail

Order intake

Auto-generated order numbers, customer name/phone, a structured address form (building, address lines, postcode, city, state), service type, quoted price, optional technician and schedule, admin notes, and checklist customization before work begins.

Structured addresses & maps

Address parts are stored as separate columns for editing and filtering, then composed into a display string. The service address in the order detail opens in Google Maps.

Audit history

Every tracked action is recorded with actor, timestamp, and before/after values, rendered as a readable diff. Technicians see only their own orders' history.

Checklist proof & evidence

Technicians attach photos to checklist items (persisted and committed to storage) and upload up to six private evidence files per job. Files open through short-lived signed URLs — never public.

Payments & receipts

Field payments at completion and admin collections with notes. Receipts can be extracted by AI and are attached to the payment record, viewable by managers.

Notifications & messaging

Assignment, completion, correction, and payment notifications with unread state and realtime sync. Internal direct and order conversations with mentions and attachments.

KPI dashboard

Date-scoped metrics: completed jobs, service value, payments/outstanding, postponements, technician charts, and a leaderboard.

WhatsApp handoffs

User-activated wa.me deep links for assignment and feedback, audited with delivery_confirmed=false. A plug-and-play provider template exists for real delivery receipts.

5AI features

AI runs entirely server-side; the browser never holds model keys, and every AI read is scoped by the signed-in user's own permissions.

Ops assistant

Ask operational questions in plain language — orders, payments, performance, workload, staff, messages, reviews, or analytical questions. Gemini plans exactly one role-allowed, read-only tool; the tool retrieves authorized rows; Gemini formats the answer with citations. Write-style or unsupported requests are declined.

Extract with AI (orders)

In the New Order dialog, upload a quotation, invoice, or client form (PDF, DOCX, TXT, Markdown, or photo) and Gemini returns a strict JSON schema — customer, phone, address parts, service, details, amount, date. Values are deterministically normalized and pre-filled for review.

Extract from receipt (payments)

Admins and technicians upload a receipt; the AI extracts amount, method, date, and receipt number, pre-fills the payment fields, and attaches the receipt to the payment record.

Guarded analytical SQL

Analytical questions generate SQL that sqlglot validates: no writes or DDL, no system catalogs, only reviewed assistant_analytics_* views, bounded joins/nesting/limits/date ranges. Execution runs through a capped, timed RPC with the caller's JWT, so row-level security still applies to every result.

Workload insight

A dedicated read-only tool returns per-technician completed jobs and service value with the team average, so the assistant can answer questions like "which technician might be overloaded this week?" by comparing real counts against the average.

Design rule: AI is prefill-only for money and orders — it fills forms for human review but never commits anything itself. Every AI run is audited with a correlation id and safe metadata only.

The same architecture in a layered view:

Browser (Next.js 16 + React 19)

Authenticated Supabase client + Backend-for-Frontend routes. Never receives the service-role key or AI model keys.

Next.js BFF routes

Forward the user's JWT to the AI service and provider APIs; issue short-lived signed URLs for private files.

Supabase (PostgreSQL)

RLS is the security boundary. Every write goes through versioned, role-checked RPCs with optimistic concurrency and atomic audit events. Realtime events are debounced into authoritative snapshot refreshes. Private storage buckets hold evidence, receipts, and documents.

Agno AI service (FastAPI)

Reads data through the caller's JWT (RLS applies), runs Gemini tool planning and response formatting, validates analytical SQL, and audits every run. The service-role key is confined to document intake and webhook callbacks.

Google Gemini

Plans one role-allowed read-only tool per question, extracts structured fields with JSON schemas, and summarizes authorized evidence.

Why these decisions?

  • RLS as the single boundary — the UI and the AI go through the same authorization, so there is no second security model to get wrong.
  • Versioned RPCs for all writes — workflow rules and auditability live in the database, not just in components.
  • Read-only, evidence-bound AI — satisfies the assessment's "controlled queries, not unrestricted database access" requirement.
  • Private storage + signed URLs — evidence is never publicly readable.
  • Pluggable providers — WhatsApp delivery tracking can be added without touching callers.

8Security & authorization

  • Row-level security on every table scopes reads by role, assignment, and ownership.
  • Versioned RPCs re-verify role, assignment, state, and optimistic version on every write.
  • Service-role confinement — the privileged key is only used for document intake and provider webhooks.
  • BFF pattern keeps secrets server-side.
  • Private files open only through short-lived signed URLs.
  • AI read-only — cannot create, edit, or delete records; refused write/unsupported requests.
  • Webhook verification (WhatsApp) uses token challenge + provider parsing.

13Known limitations

  • wa.me deep links confirm only that a handoff was opened; delivery tracking is a ready-but-unconfigured template.
  • No offline field drafts; weak connectivity needs encrypted local drafts and conflict-aware retry.
  • Local seeded credentials; production should use SSO/MFA and a profile-derived directory.
  • Evidence needs production retention, malware scanning, and lifecycle policies.
  • AI quality depends on Gemini availability and document legibility; it is read-only by design.

14FAQ

What can the AI do?
Answer operational questions from authorized data, extract order and receipt fields into prefillable forms, run guarded analytical SQL, and compare technician workload against the team average. It cannot write data.
Is the AI allowed to create or change orders?
No. AI fills forms for review; orders and payments are still created through the same validated, versioned RPCs.
Does the app confirm WhatsApp delivery?
Not yet — the assessment permits a deep link. Real delivery status is supported by a plug-and-play provider template once Meta credentials are configured.
Who can see audit history?
Admins and managers see all audit events; technicians see audit history only for orders assigned to them.
Where do evidence photos live?
In a private Supabase Storage bucket, opened via short-lived signed URLs.
